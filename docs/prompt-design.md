# 프롬프트 설계서

## 1. 목표
내 개인 일정과 할 일을 한곳에서 llm-wiki를 관리하여 사용할 거야. 이걸 우리 서버에 배포하여 사용 할 예정이야.
그러고 프론트 사이트도 배포하고 관리할 생각이야.
## 2. 맥락
- 사용자는 나 한 명이야.
- linear의 형태로 개발이 되면 좋겠어.
- 날짜가 있는 일정과 날짜 없는 할 일을 함께 관리하고, 끝낸 것은 완료 표시하거나 지웁니다.
- 항목마다, 또는 독립적으로 마크다운 노트를 쓰고, 노트끼리 [[노트제목]]으로 연결해.
- 최종 방향은 서버에서 LLM API를 호출해 노트를 요약·검색·질의하는 것입니다.
- 내 배경: Java/Spring을 능숙하게 쓰는 백엔드 개발자이고, JavaScript와 React도 할 수 있습니다.
  다만 이것은 참고용일 뿐, 기술 선택을 제한하려는 것이 아닙니다.
  유지보수 부담, 개인 서버 환경, 확장성을 기준으로 가장 좋은 스택을 제안해 주세요.
  내가 익숙한 기술이 아니더라도 더 적합하면 그쪽을 추천해도 됩니다. 단, 그 경우
  학습 비용이 어느 정도인지 함께 적어 주세요.
## 3. 제약
- 배포 대상은 내 개인 서버 한 대(docker 가능) + cloudflare Page 
- postgres를 활용할거고, 프레임워크는 python 서버나, spring을 활용해주면 좋을거같아.
- 예시 데이터 굳이 필요 없을거같아.
## 4. 출력 형식
기술 스택 표(계층 / 선택 / 이유 / 대안 / 학습 비용)
프로젝트 디렉터리 구조와 모듈별 역할 한 줄씩
데이터 모델(일정·할 일 항목, 노트, 태그, 노트 간 링크)과 테이블 관계
REST API 목록(메서드, 경로, 요청/응답 요약, 검증 규칙)
화면에 보일 요소를 위에서 아래 순서로
배포 구조(구성, 환경변수, 데이터 백업, HTTPS)
1차 / 2차 버전 범위 구분(2차: LLM API 연동, 전문 검색, 임베딩 검색 등)
완료 기준별 확인 방법
## 5. 완료 기준
- 내 일정을 한눈에 확인할수 있다
- 어떤 기기에서든 배포된 페이지를 확인할 수 있다
- 실제 배포가 모두 되어있다
- 일정을 삭제, 생성, 수정, 조회할수 있다.
- 내용이 서버가 내려가거나, 사이트에서 나가도 저장되어있다
- 노트 전체를 내보낼 수 있다.
